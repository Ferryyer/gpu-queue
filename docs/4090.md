# 4090 联网申请适配

任务文件显式设置 `resources.type = "4090联网"`。省略类型仍为 `H卡离线`；不修改已有任务类型。模板见 [`examples/4090.task.template.json`](../examples/4090.task.template.json)，所有占位符须替换为本人 HOME 下真实存在的项目、代码和解释器路径。

`gpus` 为 1–4 张；`memory_gb` 为每卡十进制 GB，按实际任务估算，未知时设为 `null` 并串行。准入使用该申请的新鲜遥测、实际显存和预留，不假设 4090 具有 H 卡容量。预计时长范围为 `2/60 <= estimated_hours < 18`，默认 17 小时；时长是规划值。

在 CPU 准备代码、环境、数据后，先执行 `gpuq validate --manifest <任务JSON绝对路径>`，再 `gpuq submit --manifest <任务JSON绝对路径> --source Codex`。提交只固定版本；本人在网页点击“开始”才授权申请或复用 GPU。切换 Auto、收到交接包或升级客户端都不授权新任务。

## 申请、等待与就绪

任务服务先读取本人飞书真实表单，再保存 UUID、表单字段和启动授权，最后提交；继续使用既有众解深算 Profile 和 `--as user`。HTTP 超时保留 `submission_unknown` 和同一 UUID 核查，禁止换 UUID 重投。

平台排队、HTTP 提交、服务端初始化和已就绪卡上的只读探针分别计时。运维交接的服务端规则：首次确认 RUNNING 后，总初始化预算 1500 秒（管理连接 600、成员/安全/CUDA 720、余量 180），跨重试不重置，平台排队另算。此预算由服务端执行；本地没有相应阶段接口，继续显示等待有效就绪通知，不推测服务端内部进度，也不把本地 HTTP 或探针超时统一改为 25 分钟。

RUNNING、SSH 可连接或显卡枚举均不单独证明完整就绪。客户端通过受信发送方、未删除且精确关联申请 UUID 的首行通知，再结合该申请的新鲜遥测准入；完整 UID/组、共享盘读写、私有目录隔离、安全接口和普通成员 CUDA 验收仍属于服务端。
