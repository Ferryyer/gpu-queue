# 成果网页转发

在「服务器」选择运行成果网页的服务器，进入详情工具栏的「端口映射」，点击「打开成果链接」。粘贴 Codex 给出的 `http://127.0.0.1:8780/...` 链接，点击「建立转发并打开」。

Queue 先绑定本机 `127.0.0.1:8780`，然后通过已认证的 SSH 自动执行内置初始化脚本：检查本人私有成果服务，已运行时直接复用；尚未运行时在本人账号下安装并启动。只有服务准备成功后才打开浏览器。配置会保存，再次使用可直接打开已有转发开关。

服务器通过本人专属 Unix socket 提供网页，目录权限 700、连接文件权限 600，不新增服务器 TCP 端口。已有 fshare 的登记列表、链接 token 和命令保持不变。不依赖 Codex、不下载远程安装脚本、不需要 sudo；远端需要 Python 3 和 SSH。

同一个服务下的多个成果网页、图片、脚本都共用这条转发。不必每个成果单独配置。固定 8780 是本机浏览器入口，并不要求服务器也监听 TCP 8780；其他端口运行的应用不会自动归并进来。

首次使用后，远程 Codex 可以这样登记成果目录：

```
~/.local/bin/fshare /完整路径/成果目录
```

把输出链接发给用户即可。只提供登记过的文件或目录，凭据路径和越界文件不能通过该服务读取。已有成果仍使用原来的链接。

本机 8780 同时只能用于一个目标。如果端口被占用，Queue 会保留原服务并显示错误，初始化脚本不会执行。退出 Queue 或 SSH 断开后，再次打开成果转发会自动检查并准备服务；当前没有后台自动重连。普通端口映射不会执行这个初始化脚本。

维护者可审查 `serverbox/crates/sbm_parser/src/scripts/result_preview/` 下的 Python 源码。`scripts/build_result_preview_asset.py` 将完整脚本打包为应用内置资源；`--check` 验证资源与源码一致。运行 `ensure.py`（同目录保留 `fileshare.py`）也可以独立准备服务器。
